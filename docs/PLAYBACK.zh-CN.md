# 浏览器放映

[简体中文](PLAYBACK.zh-CN.md) | [English](PLAYBACK.md) · [项目架构](ARCHITECTURE.zh-CN.md)

现有播放器可导入本地已发布订阅或可访问的 M3U 链接，支持搜索、上一台/下一台/随机、数字台号、全屏和手机布局。它能独立运行，不要求采集、检测、OBS 账户或本地检测数据库。

## 只运行放映

```bash
# 实际密码通过私有服务环境设置，不提交到仓库。
export IPTV_TV_PASSWORD='choose-a-private-password'
python3 -m iptv_qa play --host 127.0.0.1 --port 8089
```

访问 `http://127.0.0.1:8089/tv/`，登录后粘贴 M3U 链接。根路径 `/` 跳转到 `/tv/`，纯放映模式不启用报告和状态接口。本地预设订阅通过 `--data-dir ./data` 指向已发布目录；远程预设通过 `--public-base https://YOUR_PUBLIC_PLAYLIST_BASE/` 指定。自定义链接无需这两项。未设置密码时，纯放映模式明确报错并停止启动。

`python3 -m iptv_qa dashboard --data-dir ./data --port 8088` 只提供报告，即使设置了密码也不加载播放器。`python3 -m iptv_qa serve --data-dir ./data --port 8088` 共用一个服务，设置密码后启用 `/tv/`。旧的 `python3 web.py ...` 保留共用模式。参见[部署模板](DEPLOYMENT.zh-CN.md#独立模块)。

## 换台与媒体传输

- 快捷入口为三个：**综合频道**、**今日补充**、**英语频道**。启用总表时各自读取管理视图，每台最多五条优先线路；未启用时综合入口兼容 Set1–3，备用按归一化频道身份匹配，不因缺行或排序变化而播错频道。原订阅网址和自定义 Top3 输入仍可用。
- Set4 保留独立顺序，不跨 Set1–3 回退；可通过公开基址的 `iptv_set4.m3u`，或本地 `DATA_DIR/extras/iptv_set4.m3u` 提供，定时质检不覆盖。英语入口使用 `iptv_english.m3u`，本地为 `DATA_DIR/english/published/iptv_top3.m3u`。
- 普通模式在当前频道所有线路失败后报错。增强模式还会在10秒无数据时换备用，全部线路失败再换频道。默认**顺序换台**，33台的三条线路均失败后尝试34台；可切到**随机换台**，本轮不重复尝试已失败频道。整表遍历一轮后停止，手动选台或重试会开启新一轮。这些模式不会删除频道或改动OBS。旧频道的迟到报错不会干扰新选择。
- **多源竞速**（hedged requests，默认开启）：频道有多条线路时，最多五条（该频道全部线路）同时开始加载，先解码出画面的一条立即播放，其余线路马上丢弃。全部线路因编码问题失败时回退服务器转码；其他整体失败从第一条未竞速线路起继续顺序尝试。控制栏开关可关闭竞速、恢复逐条顺序尝试；竞速会让换台瞬间的带宽按参与线路数成倍消耗几秒钟。浏览器限制自动播放时仍会提示点“播放”，但竞速换线产生的过期播放请求不会再误显该提示，且画面真正开始播放后提示自动消失。
- 同源代理改写 HLS 清单、分片、密钥、音轨和初始化地址，保留频道 User-Agent/Referer 设置。hls.js 及许可证随包安装，浏览器实际支持的编码仍会影响播放。
- 解码失败或有声无画面时，前端可请求 FFmpeg 回退转码为 H.264/AAC，封顶 720p、2 Mbps。纯音频源会显示提示，转码不能补出源中不存在的视频。
- 默认最多两路同时转码，空闲 90 秒后回收。可用 `--transcode-limit`、`--transcode-idle`、`--ffmpeg` 调整，也支持 `IPTV_TV_FFMPEG`。直接代理播放无需 FFmpeg。服务关闭时停止其创建的转码进程并清理临时文件。

## 直播地址跳转

部分频道入口会跳转到 CDN 的另一个目录，返回的清单只写相对文件名。代理现在按跳转后的最终响应地址解析子清单、分片、密钥和初始化文件。此前按原入口地址拼接，会出现“清单拿到了，视频却从错误目录请求并返回 404”的问题，因此 FFmpeg 能解码而浏览器无法起播。

可以把清单理解为取货单：入口通知取货点已搬到新地址，但取货单上只写“隔壁仓库”。代理必须以新取货点为参照，不能回到旧地址找仓库。此修复针对网页媒体代理，不调整检测器的质量门槛。

## 面向电视 App 的令牌竞速订阅

启用总表并在私有服务环境配置令牌（`IPTV_TV_TOKENS`，逗号分隔）后，任何 M3U 播放器——Apple TV / Android TV 应用、VLC、TiviMate——都可以加载 `http://HOST:PORT/tv/playlist.m3u?token=令牌&view=main|supplement|english`（view 默认 main）。订阅里每台频道一条，地址是竞速端点：服务端并发探测该台的排序线路，第一个“HLS 清单有效且首分片有数据”的线路胜出并由服务器透明中继，各线路的 User-Agent/Referer 由服务端注入，播放器完全不需要理解 `#EXTVLCOPT`。改写后的子地址走平行的令牌认证 `/tv/rstream/` 路由，因为浏览器用的 `/tv/stream/` 需要会话 Cookie。

胜者按（视图, 频道）缓存约 60 秒，回看不再重复竞速；全部线路竞速失败时回退 0 号线路。令牌绝不放行管理接口或浏览器端点；校验为常数时间比较，`IPTV_TV_TOKENS` 留空则端点整体关闭（404）。令牌的敏感度等同播放密码：不进 Git 和日志；由于令牌经查询串明文传输（与现有密码 Cookie 同一暴露面），广泛分享订阅链接前建议先加 HTTPS 反代。

## 访问与适用范围

播放器使用共享密码和 HttpOnly、SameSite=Strict 会话 Cookie，错误密码延迟一秒返回。会话及已加载频道保存在内存，重启后清空。当前适用于个人或可信小范围使用，不是多租户账号系统；报告页面也不会自动继承播放器密码保护。

代理仅转发已加载清单中注册的地址，并拒绝部分云元数据地址。但已登录者提交的清单可以引入上游地址，这不是完整的 SSRF 隔离。限制可信访问者及网络范围；对外开放时使用 HTTPS 和适当访问控制。

代理和转码按观看人数占用服务器带宽与算力。自动播放及编码支持依设备而异；公网服务器无法直接访问内网组播，需要上游网关。旧[可行性研究](WEB_PLAYER_FEASIBILITY.zh-CN.md)仅保留历史背景，以本页描述的已实现行为为准。

## 受管Top5与可恢复清理

启用[频道总表](LIBRARY.zh-CN.md)后，快捷入口读取数据库视图，每台最多五条线路，`/tv/manage/` 管理同一批记录。失效清理只清理当前视图，排队生成版本发布并支持恢复。首页区分当前总表与历史检测，将兼容下载收进次级入口。

受管会话的控制栏还有**报错清理**按钮：画面内容与频道不符（广告、失效二维码提示等）时点击，确认后只清理当前线路而不是整台，播放器立即从该台剩余线路的第一条重新竞速续播（竞速关闭时按顺序重试）；被清理线路已从播放所依据的实时线路表中消失，无需会话内额外跳过。该台一线不剩时整台移入清理区并自动切到下一台。两者都可在管理页恢复（启用线路/恢复频道），定时质检不会自动恢复人工清理的线路。与失效清理不同：失效清理是对技术性起播失败的自动判定，报错清理是观众对内容不符的主动上报。
