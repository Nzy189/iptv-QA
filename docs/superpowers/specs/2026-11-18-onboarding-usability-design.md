# 新用户上手易用性改进 · 设计文档（2026-11-18）

状态：已获用户确认方案 A（文档为主 + 小代码补齐），待实施。

## 背景：陌生人视角的四个问题

1. **"我有自己的源，怎么导入"没有明确路径。** `configure.py --source` 早已支持替换默认源，但只写在 DEPLOYMENT.md 第 50 行；README 快速上手只给了 `run`（完整流水线，含几万候选源的目录发现），陌生人照抄会跑一个远超预期的重任务。
2. **本地文件导入未文档化。** 源通过 `urlopen` 拉取，`file://` URI 可行（configure.py 内部第 29 行已在用），但 `--source` 不接受普通本地路径，也没有任何说明。
3. **功能列表偏营销、不平铺。** README 的 "Why iptv-QA?" 是收益话术，缺少一目了然的"能做 / 不做"清单。
4. **没有时间预期。** 深度检查至少 30 秒观察 + 30 分钟后重连验证，首次出结果约 30–60 分钟，README 完全没提。

## 目标

一个有自己 M3U 的陌生人在 README 首页 1 分钟内找到导入路径并知道要等多久；任何人 1 分钟内看懂这个项目能做什么、不能做什么。

## 改动清单

### 1. README.md / README.zh-CN.md 快速上手重构为两条路径

- **路径 1 · 检查自己的播放列表**（放在最前，新用户默认路径）：
  ```bash
  python3 scripts/configure.py --output config.local.json --data-dir ./data --source <M3U 地址或本地文件>
  python3 -m iptv_qa check --config config.local.json
  ```
  说明：`--source` 可重复传入多个订阅；支持 http(s) URL 和本地文件路径；`check` 跳过目录发现，只检查配置的源。
- **路径 2 · 完整流水线**：现有 `run`，明确标注会先做目录发现（默认公共源，候选量大）再全量质检，适合想复刻演示订阅的场景。
- 浏览器播放（`play`，不跑 QA 直接放外部 M3U）保持现有内容，归入路径说明。

### 2. 新增"功能清单"节（What it does / What it doesn't）

两列平铺表，放在 "Why iptv-QA?" 之前：

能做：真解码检查（视频帧 + 进度）、源排名与合并、Top3/Top5/三套单源清单、稳定分级、浏览器播放 + 转码兜底、定时任务与发布保护、报告/历史导出、可选 OBS 上传。
不做：不保证不间断播放、不内置固定频道库、不破解或代付任何付费源、不做 EPG。

"Why iptv-QA?" 收益表保留，位置后移。

### 3. 时间预期说明

快速上手内加一行：首次检查约 30–60 分钟出结果（每源至少 30 秒深度观察 + 30 分钟后新连接复验），慢即是质量门槛；`run` 完整流水线视源数量可能数小时。

### 4. docs/DEPLOYMENT.md / DEPLOYMENT.zh-CN.md 同步

`--source` 说明（含本地文件支持）保留在部署文档，并加跳转锚点与 README 互相引用。

### 5. scripts/configure.py 小代码补齐

`--source` 传入的值若存在为本地文件路径（`os.path.exists`），自动转 `Path(...).resolve().as_uri()` 再写入配置；URL 原样保留。约 3–5 行改动。

### 6. 测试

`tests/` 新增针对 configure.py 本地路径转换的单测（URL 不变、本地路径转 file:// URI、不存在且非 URL 的值报错或原样保留——按实现定为报错）。

### 7. PROGRESS.md 更新

按项目规则记录本次改动与验证证据。

## 验收标准

- 按 README 路径 1 的命令，用一个本地 M3U 文件能完成配置并启动 `check`（不要求跑完全程，验证配置生成与源可读即可）。
- `python3 -m unittest discover -s tests -v` 全部通过。
- 中英文 README、DEPLOYMENT 内容一致，语言切换链接保留。
- README 首屏（不滚动或只滚动一屏内）能看到"导入自己的源"入口。

## 不做的事

- 不改检测规则、排名逻辑、发布流程。
- 不做交互式配置向导、快速检查模式等新功能。
- 不改动生产部署；发布节奏照旧（公共仓库更新不自动部署）。
